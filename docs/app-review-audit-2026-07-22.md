## 上架阻断项

### 1. 隐私声明入口无行为，且没有可核验的隐私政策 URL

`Index.ets` 的“隐私声明”只是静态 Row，没有 `onClick`。应用会处理远端设备 ID、主机名、Server Pro 用户名/访问令牌、连接密码、地址簿、局域网设备信息、聊天及剪贴板文本，必须在隐私政策中逐项说明处理目的、存储位置、保存期限、第三方/自建服务器传输、删除方法和联系方式，并确保应用市场填写的 URL 与应用内入口一致且可访问。

### 2. 连接密码提示与实际行为相反

连接弹窗写着“密码仅用于本次……不会保存在手机上”，但连接成功后会调用 `RecentHostStore.save()`，并把密码写入 HarmonyOS Asset Store。安全存储方式本身合理，但提示必须改成真实表述，并提供“记住密码”显式开关（默认值和隐私政策保持一致）以及清除已保存密码的入口。

### 3. Server Pro 登录允许 HTTP，可能明文传输账户密码

`ServerProfileStore.validate()` 接受 `http://`，`ServerProApi.login()` 会把用户名和密码放入 JSON 请求体。当前“允许回退到不安全 TLS”开关没有真正约束该登录路径。发布版应强制 HTTPS；如确需内网 HTTP，必须采用明确的高风险确认且不能作为默认行为，也不应对公网地址开放。

### 4. 品牌与开源许可材料不足

应用名、界面标题和 `rustdesk.com` 容易让用户认为这是 RustDesk 官方应用。若没有品牌授权，应使用独立产品名，并在介绍中写“兼容 RustDesk 协议的第三方客户端”，避免官方网站链接造成官方背书印象。项目使用/衍生 RustDesk AGPL 代码，但根目录缺少完整 AGPL 许可证、版权声明、第三方 NOTICE 和对应源码获取方式；上架前需完成开源合规，并确认 RustDesk Server Pro 相关名称、图标和接口使用权。

### 5. 签名口令写入工程配置

`build-profile.json5` 直接包含 keystore 与 key 口令和本机绝对路径。应立即轮换相关调试/发布凭据，把秘密移出工程和交付包，通过 DevEco/CI 安全变量注入；发布包必须使用正式发布证书，而不是当前默认调试签名。

## 高优先级整改项

### 6. 存在可见但无功能的设置和占位功能

“Socks5/Http(s) 代理”“语言”“明亮主题”传入空 action，点击无效果；会话菜单还显示“开始录屏（即将支持）”“复制指纹（即将支持）”。审核版应实现这些功能，或彻底移除/隐藏入口，避免被判定为功能不完整或误导。

### 7. 版本信息不一致

包清单为 `versionName: 0.1.0`，应用关于页显示 `Version: 1.5.0`，README 又描述不同里程碑。应让 UI 从包管理信息动态读取版本，并保证应用市场、包清单、关于页和隐私政策一致。

### 8. 官方身份表达与网站入口不完整

关于页显示 `rustdesk.com`，但没有点击行为，也没有第三方客户端/版权归属说明。应改成真实产品官网、支持邮箱、隐私政策、用户协议、开源许可页面，并明确开发者主体。

### 9. 编译仍有未处理异常警告

构建成功，但网络发送、Asset Store 写入和局域网 Socket 操作存在 “Function may throw exceptions” 警告。正式送审前应补齐异常处理，并在弱网、断网、后台恢复、锁屏输入、Server Pro 不同版本下完成稳定性回归。

### 10. 2-in-1/PC 声明需要真机覆盖证据

清单声明支持 `phone`、`tablet`、`2in1`，但 README 仍说明 x86_64 Native 输出未完成。若目标审核设备存在相应架构，可能安装或启动失败。上架设备范围应与实际 Native ABI、布局、鼠标键盘输入和后台策略测试结果一致。

## 建议送审前最小清单

1. 完成隐私政策、首次必要告知、应用内可点击入口和数据清除入口。
2. 修正“密码不保存”的错误文案，增加“记住密码”选择。
3. 强制 Server Pro HTTPS。
4. 确认品牌授权；无授权则更名并补充第三方兼容声明。
5. 补齐 AGPL/第三方许可与源码获取页面。
6. 删除所有无功能入口，统一版本信息。
7. 轮换并外置签名凭据，生成正式 release 包。
8. 在手机、折叠屏、平板和 2-in-1/PC 目标 ABI 上完成安装、启动、连接、后台恢复和输入回归。

本报告是基于当前工程的静态检查和本地构建预审，不等同于华为应用市场最终审核结论。
